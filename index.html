Proposta de Desenvolvimento

Plataforma de Gestão Unificada e Motor Financeiro

PROPOSTA APROVADA

Cliente: Dom Lux Brindes

Consultoria: GSTek - Engenharia de Software Corporativo

Stack Tecnológico: Python, Django, PostgreSQL, Celery, Docker

1. O Problema Atual (A Dor)

Hoje, a Dom Lux perde tempo precioso exportando relatórios mensais separados do Mercado Livre e da Shopee para consolidar tudo manualmente em planilhas. Para cada venda, ela precisa cruzar manualmente os dados para chegar nos 12 indicadores-chave (Custo, Venda, Impostos, Caixa, Lucro e Margem de Contribuição) de seus cerca de 500 SKUs.

2. A Solução Proposta (O Fim das Planilhas)

Desenvolver uma Plataforma de Gestão Multicanal sob medida. O sistema vai substituir as planilhas fragmentadas, conectando-se diretamente às plataformas de venda para automatizar a captura de dados e o cálculo financeiro de cada centavo que entra e sai.

A plataforma será construída baseada nos seguintes módulos:

Módulo 1: Motor de Captação de Pedidos (Automação)

  • Integração API (Automática): Robôs de sincronização que puxam automaticamente todos os pedidos do Mercado Livre, Shopee, Amazon e NuvemShop em tempo real (ou periodicamente).
  • Lançamento Manual Rápido: Uma tela otimizada para registro de vendas sociais (WhatsApp e Instagram).
  • Aposentadoria de Relatórios: A cliente não precisará mais exportar relatórios nas plataformas; o sistema fará a varredura e importação contínua de todos os dados do pedido.

Módulo 2: Gestão Inteligente de Custos (Base do Lucro)

Para que o sistema calcule a margem sozinho, ele precisa conhecer os custos.

  • Cadastro Unificado de Produtos (500 SKUs): Base central da inteligência.
  • Matriz de Custos: Cada produto terá campos para Custo Base e Custo de Embalagem.
  • Matriz de Impostos: Configuração de Imposto Individual (%), garantindo que o cálculo bata com a realidade contábil.
  • Regras das Plataformas: O sistema vai considerar as taxas e comissões que os marketplaces retêm na fonte.

Módulo 3: Inteligência Financeira e Painel de Lucro (O Coração)

O sistema replicará a lógica que já é utilizada, porém de forma automatizada, instantânea e unificada.

  • Geração Automática de DRE por Pedido: O sistema exibirá as colunas: ID, Data, Cliente, Nº Pedido, Produto, Custo, Valor Venda, Imposto, Caixa, Lucro, % de Lucro, Margem de Contribuição.
  • Dashboard Unificado: Um painel onde ao selecionar "Mês de Outubro", o sistema consolida o lucro real somando Mercado Livre + Shopee + NuvemShop + Amazon + WhatsApp.

Módulo 4: Controle de Acesso e Usuários

  • Sistema de Permissões: Separação de acesso para os 4 usuários iniciais.
  • Exemplo: Um usuário de "Operação" pode lançar vendas do WhatsApp, mas não pode ver a coluna "% de Lucro", que fica restrita aos administradores.

3. Escopo Opcional (Futuro)

Oportunidades de evolução para a plataforma (orçamento separado):

  • Conciliação Bancária via OFX/API: Importar o extrato do banco e cruzar com os repasses previstos.
  • Gestão de Estoque Unificado: Trazer o controle de estoque de terceiros para dentro do sistema GSTek (baixa automática).
  • Esteira de Produção: Módulo "Kanban" para gerenciar os itens personalizados, anexando artes aprovadas.

Matriz de Viabilidade de Integração de APIs

Para garantir a viabilidade técnica antes de precificar o projeto, mapeamos exatamente o que conseguimos extrair de forma automatizada das 4 plataformas e o nível de complexidade.

1. Mercado Livre

🟢 Muito Alta
  • Autenticação: OAuth 2.0 (Fácil)
  • Pedidos: Sim. Endpoint /orders.
  • Taxas: Sim. Retorna tarifa de venda e frete.
  • Recebimentos: Sim. Integração com API Mercado Pago.

2. Shopee

🟢 Alta
  • Autenticação: App Key (Exige aprovação).
  • Pedidos: Sim. Endpoints GetOrderList.
  • Taxas: Sim. Retorna comissão, taxa de frete e vouchers.

3. NuvemShop

🟢 Muito Alta
  • Autenticação: OAuth 2.0 (Fácil).
  • Pedidos: Sim. Traz itens e frete.
  • Taxas: Apenas o valor do pedido. A taxa de cartão vem do gateway (ex: PagSeguro).

4. Amazon SP-API

🟡 Complexa
  • Autenticação: AWS IAM + OAuth. Muito rigoroso.
  • Pedidos e Taxas: Sim (Orders API e Finances API).
⚠️ PII: A Amazon oculta dados do cliente após a entrega. Sistema deve salvar imediatamente.

Conclusão Técnica

  • É 100% possível construir a unificação financeira.
  • Cálculo de Custo: A API manda por quanto foi vendido. O sistema interno é quem vai ter a tabela "Caneca = R$ 15,00" para fazer a matemática (Venda - Taxa - Custo = Lucro).
  • Mapeamento de SKUs (De/Para): O sistema precisará de uma tela para vincular códigos externos (ex: MLB999) ao produto interno.
